1. `fault-recovery-natural-1`：测试脚本同步 POST 的 40 秒等待先于实际 Run 结束，异常退出。容器 finally 恢复；不能把恢复后才结束的调查当作完整停机验收。脚本现在允许该同步请求等待 900 秒，并继续按真实 Run 的终态判断；不改变应用内预算，提前保留 sessionId。

3. `fault-recovery-natural-3`：真实 Luna 响应已核对，但节点 Schema 拦截了额外的 `resolvedRequest:["window"]`。根因是内部 JSON 输出契约与通用 Router“必须追加路由字段”、用户可见 outcome 协议同时拼入 Prompt。修复将批准定义中的 outputContract 传入内部 Agent；JSON 节点只使用自己的 Schema，Router 读取已有字段，不再要求额外路由字段。普通对话仍保留 outcome 和证据协议。Schema 校验没有放宽。

相关代码及 SHA256 见 `recovery-source-manifest-20260927.json`。修改涉及失败分类、内部 Agent 配置投影、Prompt/Router 拼装、内部结果遥测，以及 4 个验收脚本。测试新增 `OpsModelTlsRecoveryTest` 与 `OpsStructuredWorkflowPromptTest`。
