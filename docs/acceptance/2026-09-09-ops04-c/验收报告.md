## 完成范围与文件

- `WorkflowChangeVerificationPolicy.java`：前后十五分钟、各至少一百请求；按批准版本、目标、执行 operation hash、完整 receipt 与时间冻结窗口。正常发布同时检查绝对 SLO、健康可比基线及相对变化；恢复性变更使用预先批准的绝对目标。仅允许同版本同条件扩至三十分钟一次。缺失负载可比约定不自行猜测容差。
- `OpsWorkflowChangeContextReader.java`、`JdbcChangePackageQueryAdapter.java`：从应用查询服务读取批准快照和执行记录、权威 epoch 时间。请求中的 `LANDED`、预期版本和放宽阈值不能授权或改变验收标准。
- `OpsGraphRouterNodeExecutor.java`、`OpsChangeVerificationReportFormatter.java`、节点定义校验与运行装配：持久化结构化规则结果，输出中文报告，明确区分执行完成和验收通过。
- `WorkflowObservabilityPolicy.java`：只把有实际请求增量的版本和路由纳入比较，避免残留的零增量 counter 污染基线。
- `deploy/acceptance/observability-mcp.py`、`scripts/seed-observability-mcp.py`：新增实际 `/version` 只读查询；显式重新发现目录，保留原四项已审核 contract，正常审批第五项工具。
- `scripts/fixtures/workflow-business-change.json`：13 节点 / 15 连接；完整采集三次逻辑查询，扩窗再三次，含重试最多十二次派发。
- 初始化与测试：`seed-change-verification.py`、`test-change-workflow-runtime.py`、`collect-change-policy-evidence.py`、`test-version-recovery-runtime.py`；配套域规则、Router、真实数据和 HTTP MVC 测试。
- `GlobalExceptionHandler.java`、`GlobalResponseStatusAdvice.java`：明确状态冲突返回 409；响应处理不再覆盖异常处理器的显式错误状态；不支持的 HTTP 方法返回 405，基础设施故障仍返回 500。

所有具体路径、源文件快照和 SHA-256 在 `source-sha256.tsv`、`source/` 中。保留此前用户工作区内容，未提交或推送。
