# 内容审查与两轮自动修订

适用当前交接 OPS-05。语义审查拒绝后，使用同一份冻结来源和原提案，模型根据审查意见自动修订，最多两轮完成的修订；仍不合格就保留失败及原稿。网络、协议或模型依赖不可用保存等待并指数退避，不占用修订轮数，也不让前台对话等待。后台模型单次仍采用用户批准的 60 秒边界。

## 持久记录与权限

新增的内容修订账本保留每轮原候选、模型原始输出、审查意见、输入/候选/模型绑定哈希、状态和租约。90 秒令牌租约与比较交换保护单一执行；领取与提交时均检查真实已验收来源。模型调用放在数据库事务外，发布时重新进行来源、风险、范围、版本、索引及审批检查。

操作类型、目标、风险、来源集合和拆分分支身份不能借修订改变。原稿与旧失败不覆盖。普通业务批准、生产执行权限仍由原有三阶段和审批链决定，Skill 只提供方法，不授予工具权限。

已完成的审查结果按候选、冻结来源、策略、实际模型/端点/提示绑定复用，防止下游重试重新抽取同一候选的结论。旧记录缺输入哈希时只允许复用同候选、同策略和同模型绑定的拒绝；旧通过结果仍须重新审查。不匹配或损坏记录不能成为通过依据。

实际模型曾生成“不绕过审批”的限制文本，旧检查误把它当危险指令。现在统一在领域策略中逐字段、逐条款识别明确的禁止语义；正向绕过指令、双重或不明确否定、对比句后的危险内容和跨字段拼接仍拒绝。危险脚本检查保持原门槛，不因禁止措辞放行。
