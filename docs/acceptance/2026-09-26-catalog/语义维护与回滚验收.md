# OPS-06：语义维护与回滚验收

日期：2026-09-27。用户同意按开源调研结论做简单实现。模型仍为 gpt-5.6-terra，未引入训练、新审批流程或新的发布状态。

## 实现

- `SkillMaintenancePackage`：统计入口及递归引用文本；只允许修改既有说明文件，保护资源引用、frontmatter、代码块、JSON 结构和数值。不能通过把正文移到资源里规避维护触发条件。
- `OpsSkillCompressionReviewAdapter`、`SkillMaintenanceApplicationService`：后台提出语义整理后单独复核，检查不通过保留旧版本；暂时失败继续持久化退避，用户对话无需等待。
- `SkillPackageManifest.rebuild`：修复历史回滚丢失 routingProfile 的缺陷，恢复历史适用条件、禁用条件和检索词。
- `ProjectSkillVersionHistory`、`ProjectSkillGovernancePanel`：项目能力页提供版本历史、正文查看和回滚确认，切换项目不会沿用另一项目的回滚目标。
- `seed-skill-maintenance.py`、`inspect-skill-maintenance.py`：增加可重复 API 初始化和跨库只读验收；不改数据库制造审批、模型复核或发布成功。

## 通过

隔离项目 `ops-maintenance-acceptance` 的 `synthetic-semantic-method-maintenance`，v1 为合成输入：101 字节入口引用含同义规则的长方法和边界文件。真实 Terra 提出整理，另一次 Terra 调用复核后发布 v2，入口和边界资源 Hash 不变，方法文件缩短，PG 向量维度 1024、索引 READY、MySQL 活动指针一致。

通过 computer use 操作“项目 → 能力 → 版本历史 → 回滚到第 1 版 → 确认回滚方法”。首次 v3 暴露路由元数据丢失；修复部署后再次实际操作生成 v4。只读验证：原始 v1 未被覆盖，v2 仍保留，v4 全部正文和资源 Hash 与 v1 相同，历史路由一致，v4 索引 READY，活动指针指向 v4。回滚保持原维护模式，不暗中调整权限或维护策略。
