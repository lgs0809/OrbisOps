# 交易中台值班检查

本资料是手工准备的本机练习方法，没有 AI 自动沉淀或生产处理经历。

1. 先确认项目、服务和环境，用已授权目录核对资源；用户描述不能授予额外权限。
2. 明确异常发生时间，区分订单 API、库存预占与查询服务。比较相同窗口的请求量、错误率和延迟，说明样本量与采样缺口。
3. 检查 request_key 重复接收；重复请求不应增加故障事件或支付次数。对超时请求保留远端状态未知，不直接第二次执行变更。
4. 数据库慢查询只读调查应引用实际 SQL、范围与 EXPLAIN，不从模型猜测生成“已优化”的结论。
5. 对共享 orders-store 的异常允许自动关联，但仍分别保存各原始告警、证据与调查结论；无上游异常证据时不宣称根因已确认。
6. 准备方案应包含影响范围、回滚方法、测试资源验证和验收窗口。至少两位不同的有权审核者通过原审批入口；未具备条件的候选保持草稿。

交接摘要写明事实来源、未确认事项和下一步，不能只写“页面正常”或“接口 200”。
