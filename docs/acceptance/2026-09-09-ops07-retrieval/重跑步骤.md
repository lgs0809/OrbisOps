
## Qwen 服务

默认检索 endpoint 为空，不自动下载权重或改用现有 RAG / Chat 模型。代码固定 `Qwen/Qwen3-VL-Embedding-2B`（1024 维）和 `Qwen/Qwen3-VL-Reranker-2B`。Luna／Terra 仍用于此前已确认的任务归属／主推理／作者角色。

可用已有、已授权的本地 Hugging Face 快照启动 `deploy/acceptance/qwen-retrieval-gateway.py`。两个路径末级必须是已固定的 40 位 commit SHA。脚本使用 Sentence Transformers 官方接口，禁止联网下载；未提供模型目录时不会制造向量或成功响应。调用前应在隔离 Python 环境安装兼容模型卡的 sentence-transformers、transformers、torch、qwen-vl-utils 并实测；本机未执行模型安装和真实推理，不承诺任意版本组合可用。

```sh
python3 deploy/acceptance/qwen-retrieval-gateway.py --help
# 在两个 --*-dir 与 --*-revision 参数中填入真实快照，端口默认 127.0.0.1:18863。
```

后端配置 `orbisops.skill-runtime.retrieval.endpoint`、`embedding-revision`、`reranker-revision`；可选 `api-key` 与网关环境变量 `ORBISOPS_RETRIEVAL_API_KEY` 对应，密钥保留本地私密配置。网关契约为 `/embed` 和 `/rerank`，这是本仓库的接入协议，不声称所有托管服务天然兼容。

查询与文档使用固定文本预处理；截取 MRL 1024 维后 L2 归一化。返回必须包含精确模型、revision、预处理标识；客户端实际检查 1024 个有限值与范数，拒绝静默替换。重排只接收查询与原始目录文本，保留原始分数排序，不转成概率。

后台每次扫描 10 条 MySQL 目录，失败或中断的 BUILDING 投影留待循环扫描和重启恢复；READY 文档与 generation 在同一个 PG 事务提交。查询传完整当前授权、精确版本允许列表；在 MATERIALIZED 授权子集内进行有界精确向量距离检索，最多返回 20 条，不移除权限条件补齐。此批没有声称已启用 ANN/HNSW。

正文和路由 generation 的发布指针切换、文件来源投影、完整正文总预算与依赖适用性检查仍需后续收尾。旧的无 projectId 冻结引用需核查兼容性，不能通过信任请求参数绕过项目校验。

## 浏览器：审批等待期间撤销 Skill

```sh
python3 scripts/seed-related-skill-acceptance.py
python3 scripts/seed-skill-revocation-acceptance.py
```

两条种子均只创建缺少的隔离夹具，已有 Skill 修改、启停状态和历史版本保留。项目 A 的 `ops06-related-project-fixture` 应为启用；若此前手动停用，请在项目 → 能力 → 项目 Skill 管理中明确启用。全局副本不用改动。

在工作流页面搜索 `OPS-07`，打开“Skill 撤权与工作流恢复验收”，在测试页选择“打开对话手动执行”。在对话输入区明确选择这条工作流，不能用默认助手代替。提交以下 JSON，将两个 epoch 改为最近 7 天内已经过去的连续 10 分钟窗口：

```json
{"question":"核对工作流回执与实际资源状态","window":{"projectId":"ops-acceptance-a","environment":"acceptance","serviceId":"ops-acc-a-service-1","startEpoch":1788953169,"endEpoch":1788953769}}
```

正常对照：进入“查看运行”，确认只读查询后正在等待 `review` 审批，再批准并继续。两次远端回执和两次实际查询应对应两个不同的 dispatch。撤权对照：另发一轮相同目标，在等待审批时去项目 → 能力停用这份项目 Skill，再回工作台批准该轮。预期审批已记录，运行因 `SKILL_RUNTIME_ACCESS_REVOKED` 失败，只有第一次查询。审批不重新授予 Skill 权限。

只读核验脚本会写本轮专用 SQL、数据库结果和 MCP 查询账本。`--run` 使用浏览器地址栏的实际 runId：

```sh
python3 scripts/inspect-skill-revocation-acceptance.py --run "$ORBISOPS_CONTROL_RUN" --status SUCCEEDED --calls 2 --output /tmp/ops07-control.json
# 以下命令在 Skill 仍停用时执行，以便同时核验撤权时的当前状态。
python3 scripts/inspect-skill-revocation-acceptance.py --run "$ORBISOPS_REVOKED_RUN" --status FAILED --calls 1 --output /tmp/ops07-revoked.json
```

完成后，通过项目页面重新启用测试 Skill，再发送新任务。旧失败任务保持失败。可对已记录的旧审批做 8 路重复请求，确认返回 409 状态冲突、run epoch 和 MCP 调用数不变：

```sh
python3 scripts/test-skill-revocation-replay.py --run "$ORBISOPS_REVOKED_RUN" --output /tmp/ops07-replay.json
```

这些是没有调用模型的只读 Workflow 集成验收，不等于业务任务验收、Skill 自动演化成功或生产变更成功。审批、启停和工作流运行都走正常产品流程；SQL 只读，不制造成功记录。

前端更新执行 `npm run verify`（web 目录）。若常规镜像构建遇到镜像仓库不可用，可使用已安装的隔离前端镜像承载验证过的静态文件：

```sh
python3 scripts/deploy-tested-web-acceptance.py --test-log /tmp/orbisops-web-verify.log --output /tmp/orbisops-web-deployment.json
```

该脚本核验运行容器与 `web/dist` 文件字节一致，仅更新隔离 web 服务。

## 一手协议依据

[Qwen Embedding 模型卡](https://huggingface.co/Qwen/Qwen3-VL-Embedding-2B) 提供可变维度与查询／文档编码方式；[Qwen Reranker 模型卡](https://huggingface.co/Qwen/Qwen3-VL-Reranker-2B) 提供 query-document 评分接口与原始分数示例。[pgvector 文档](https://github.com/pgvector/pgvector#filtering) 说明过滤后的 ANN 召回不足及迭代扫描。此处实现选择限定授权集合内精确查询，属于工程实现选择，不是性能优越性的实测结论。
