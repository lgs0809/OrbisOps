## 手动页面流程与边界

1. 打开上述会话，点击“任务分段”，展开“追溯信息”，点击“查看本轮运行”和“技术详情”。运行完成与任务验收是不同事实。
2. 当前没有可用 Luna，真实任务保留待归属，不能继续正向验收。不要用 SQL 建段、改状态或使用固定模型响应绕过这一步。
3. 配置既定的 `gpt-5.6-luna` 后，模型实际完成归属的任务会出现“任务验收”。具有项目 `APPROVE_CHANGE` 权限且可访问该会话的用户可核对任务目标、选择本任务回执、填写结果字段及预期值。例如版本核验可选 `/version`、等于、JSON 字符串 `"fixture-1"`；这只验证版本读取目标，不代表完成生产修复。
4. 服务端计算 PASSED／FAILED／UNKNOWN，保存请求、当前 revision、实际值、回执哈希和审核人。同内容重试复用请求标识；更改已使用标识的请求内容返回 409。有未归属轮次、审批等待、未知工具结果或缺少本版本回执时不受理。
5. 回头纠正旧任务会使旧版本成功资格失效。重新执行并核验后才恢复资格。同一事故不同轮次或后续归为同一事件的来源只计一次；修改阈值不能伪造第二种运行条件。

本批尚未打通验收后重新调度既有 Evolution job，也未验收真实模型生成的 CREATE／PATCH、独立行为验证、灰度与回滚。候选经验不进入日常任务加载；后续继续扩展已有后台任务，不另建 Split／Merge Agent。
