# OPS-06：PATCH 新成功来源门槛

复查命令使用 `ORBISOPS_C_EVIDENCE_FILE` 环境变量指向本机已采集的 `c-real-component-evidence-second.json`。请先设置该文件路径；变量不生成或代替运行证据。各批次交付中的原始执行日志保持不变。

本批仍使用 OrbisOps 隔离环境，不修改 080～084 数据库迁移或现有业务记录。发布版本的 `evolution_job_id` 关联原提案中的完整来源；未发布候选不消耗来源。旧任务即使有新 revision、换条件标签，或者经迟到关联才发现与新任务属于同一事件，也不会变成新增来源。

## 边界

本批门槛发生在普通项目 PATCH 候选写入事务，使用已锁定的目录和当前关联范围。至少 3 个新增独立成功任务、至少 2 个新增任务条件必须同时满足；旧来源可作为参考，但不能提供本次修改的新证据或补条件数。不足时保留经验和冻结提案，写明确跳过原因，不标失败重试作者。缺失／损坏发布历史则阻止提交，不能解释成历史为空。扫描有明确上限并失败关闭，不静默截断计数。

本批没有完成发布前的再次验证、10／20 例独立行为验证、灰度、多资产和完整回滚；这些继续在后续批次实施。真实模型闭环仍需要已授权 Luna／Terra Provider，现有自动发布开关保持关闭。结果以同目录《验收报告.md》为准。
