# Skill 内容审查与自动修订

内容审查返回 BLOCK 时，后台可修订同一份尚未发布的提案，最多两轮。每轮保存原候选、原作者输出、完整拒绝原因、哈希和修订结果；原始已验收输入不变。发布后的 Skill 版本不进入此流程。

修订使用已配置的 gpt-6.1-terra，不改变原操作、目标、风险、来源集合或原子拆分分支身份。修订后重新检查来源有效性、方法边界、资源、内容和发布条件。两轮仍不通过，保留失败，等待新证据。修订不是批准生产操作的入口。

完成的内容审查按候选内容哈希、完整验收输入哈希、发布策略以及实际模型／端点／提示词绑定保存。技术故障后的同一提案重试复用该结论，不能反复询问直到获得 PASS；内容或绑定变化才重新审查。匹配但格式损坏的记录按故障保留，不放行为通过。来源、权限和发布检查仍在每次重试时执行。

数据库事务只负责领取、核验与提交，不包含模型网络调用。模型单次调用保持 60 秒上限；90 秒的修订租约按令牌阻止迟到回写。连接故障保留同一轮，按原后台队列指数退避，不消耗已经完成的两轮额度。并发调用不能同时持有同一轮有效租约。

`ai_ops_skill_content_revision` 保存修订台账，候选表是尚未发布提案的当前投影。更新候选和作者输出时比较旧哈希，并再次核对完整来源和未发布状态；每份旧投影先保存在台账。原方法的 24 小时提案窗口沿用原预约，不重置、不新增额度。

长解释保存在验证记录的 `result_json` 中；`reason_code` 仅存不超过 128 字符的错误标识。学习记录详情显示每轮审查原因和进度，不能将“已修订”显示为“已发布”。

自动化覆盖真实 MySQL 的并发领取、故障重试、迟到工作者隔离、两轮上限、原稿完整性、输入及频率窗口不变。真实模型的发布、复用和回退仍须另行验收，组件测试不能替代。
