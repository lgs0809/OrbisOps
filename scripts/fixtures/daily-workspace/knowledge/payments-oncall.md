# 支付清结算值班检查

本资料为人工编写的方法基线，不能冒称实际处理过的故障。

先核对时间、渠道、流水与原始请求。按 request_key 分别计算接收次数和唯一请求数，避免把回调重试当成第二次支付。对账差异需区分来源数据滞后、重复回调、状态未确认和真正金额差异。

错误率必须给出分母；没有渠道查询权限时，只能说明本地记录，不能确认渠道最终状态。超时后的状态未知不代表失败，也不允许盲目重复补扣、退款或修正。

告警可依据同时间窗、交易链和共享依赖自动关联，原始信号全部保留。关联可信度和根因确认分别表达。恢复通知只表示该信号恢复，不直接关闭仍待核验的事件或任务。

准备阶段先在独立测试目标核对幂等键与回滚路径；落地阶段必须重新校验批准的版本、hash 和资源范围。验收核对唯一业务动作、数据库状态、渠道证据与执行回执，缺任意必要证据就保持待验收。
