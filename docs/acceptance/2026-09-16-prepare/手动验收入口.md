## 只读 SQL 与交叉核对

在仓库根目录运行，输出文件必须是新的路径，避免覆盖前一轮证据：

```sh
python3 scripts/inspect-a2-landing-history.py --package-id cp-09422611-ea0c-4d26-9e08-0f704b5f2f54 --output /tmp/orbisops-landing-check.json
python3 scripts/inspect-a2-independent-postcheck.py --run-id lr-58e20758-8449-42c0-99e3-3b2558ea7e1a --output /tmp/orbisops-postcheck.json
python3 scripts/inspect-episode-retry.py --session-id chat-session-38894a11-583a-4af3-953f-bbb46083e2bc --output /tmp/orbisops-episode-check.json
python3 scripts/inspect-task-acceptance.py --episode-id task-episode-8f59791f-efbc-44e9-94de-976c00e0e782 --output /tmp/orbisops-acceptance-check.json
```

每个脚本同时保存可手动执行的 `.sql`。发布脚本检查版本对应的双人审批及唯一写回执；后验脚本逐条对照二十个真实请求；Episode 脚本只读查看暂存状态、累计尝试、输入哈希及下一次重试时间。当前后台单次模型上限 60 秒，租约 120 秒，指数退避不因页面刷新或重启而清零。

执行保存的 SQL，可使用已有容器内凭据，避免把密码写进命令历史：

```sh
docker exec -i orbisops-acceptance-mysql-1 sh -c 'MYSQL_PWD="$MYSQL_ROOT_PASSWORD" exec mysql --default-character-set=utf8mb4 -uroot orbisops_acceptance' < /tmp/orbisops-postcheck.sql
```

```sh
python3 scripts/local-acceptance.py status

```

初次环境及关联数据初始化继续使用 [已有部署和种子步骤](../2026-09-10-landing/重跑步骤.md)，种子 SQL 保留在 `scripts/fixtures/`。幂等初始化保留已存在业务行，不负责回滚成功发布。不要删除数据卷。

修改代码后先执行相应 Maven package；部署脚本要求成功日志并验证 JAR 字节一致，存在运行或排队任务时会拒绝停止服务：

```sh
python3 scripts/deploy-tested-acceptance.py --test-log /path/to/successful-package.log --output /tmp/orbisops-new-deployment.json
```

测试流量只用有结束时间的脚本，一次只运行一份。新一轮流量不能补造过去缺失的观测窗口：

```sh

```


## 真实本地检索复测

下面的目录为明确标记的合成方法，使用本地真实 Qwen 与 pgvector；不注入正式 Skill，不覆盖业务数据。第一次会建立独立 schema，SQL 和每项结果保留在指定目录。输出目录可恢复尚未完成的同版本运行；要比较修复前后，请使用新的输出目录。

```sh
python3 scripts/test-semantic-catalog.py --output-dir /tmp/orbisops-semantic-first
python3 scripts/test-semantic-catalog.py --output-dir /tmp/orbisops-semantic-paraphrases --reuse-index-dir /tmp/orbisops-semantic-first --queries scripts/fixtures/ops07-semantic-paraphrases.json
python3 scripts/test-retrieval-deadline-recovery.py --output /tmp/orbisops-retrieval-recovery.json
```

第二条只复用相同合成目录，并逐条验证当前模型和文档 generation；不是跳过索引版本检查。`result.json` 包含真实语义召回、重排降级、最终选用和失败项；`inspect.sql` 可直接检查该 schema。出现非零退出码应读取失败原因，不改期望结果来制造通过。目前中文改写最终选用仍未通过。
