# Web CI 修复与验证（2026-10-04）

本轮解决 Web 产品验收的接口夹具不一致、重复查询和连续导航竞态。最终本地 `npm run verify` 通过 278 项测试、类型检查和构建；原有 40 项浏览器测试全部通过，无跳过、失败或 flaky。真实浏览器已读取部署后的项目、工具设置、对话项目绑定和已有运行证据。本轮没有重新执行模型、工作流、审批或业务变更。

执行时间按真实日期记录：最终完整浏览器测试于 2026-10-03 17:21:41 UTC 开始，耗时 64.473 秒；对应北京时间 10 月 4 日。旧失败没有覆盖。

## 失败原因与修复

1. 全局项目选择器现在读取按权限过滤的 `chat/catalog/projects`，旧 E2E 只返回管理快照，导致目录为空。统一的 `e2e/fixtures/project-catalog.ts` 使用各测试原有项目身份返回这个接口；管理快照、读次数和作用域检查仍分别保留。执行入口补充真实产品会读取的终态 Run 接口夹具，不能用 SSE 文本代替权威终态。
2. 工作台选择已有运行时，URL 中的运行标识曾触发重新读取列表和详情。选择标识与列表加载依赖分离，保留深链接、授权读取、手动刷新及活跃运行轮询。新增测试检查列表一次读取和详情恰好一次读取。
3. 项目能力摘要与 Skill 治理面板曾各自读取同一个项目目录。两者复用 TanStack Query 的统一目录键，禁用项继续显示；项目身份、业务错误和作用域不一致仍拒绝。成功变更同时失效目录和能力摘要。
4. 快速查找曾捕获旧页面与旧项目上下文，且路由页面卸载或弹层退场遮罩会丢失刚打开的输入。所有目标通过纯函数统一构造并检查已授权目录；唯一控制器位于 Router 内、页面 Suspense 外，Sidebar 仅渲染入口。导航弹层使用 Semi 原生 `motion={false}`，关闭后立即移除旧遮罩，没有增加等待、重试或按钮特判。

BrowserRouter 可以先提交浏览器历史，再完成懒加载页面的 React 渲染。因此激活命令时读取 `window.location.pathname/search`，用于确定当前导航表面；该机制仅适用于当前 BrowserRouter 浏览器应用。浏览器 URL 不是权限凭据：目标项目必须存在于当前已授权目录，服务端鉴权保持不变。统一纯函数另有过期操作、外部项目和权限撤销测试。

原有 40 个 E2E 标题及数量与基线 `ffff8f998caeeee59b7ddf9648bb32e5e9ce51e3` 一致。新增 8 项单元测试分别覆盖查询所有权、项目目录并发与拒绝边界、导航上下文和持久控制器。已有测试没有删除；产品文案及平板布局检查按实际 UI 更新，仍检查展开/折叠行为、网格和页面无横向溢出。
