## 构建与初始化

先设置 `ORBISOPS_C_EVIDENCE_FILE` 为已有真实 OPS-04 C 组件证据文件路径。不要用合成报告替代。

```sh
mvn -B -f server/pom.xml "-Dops04.change.evidence=${ORBISOPS_C_EVIDENCE_FILE:?请设置实际C组件证据路径}" package > /tmp/orbisops-entrypoints-package.log 2>&1
python3 scripts/deploy-tested-acceptance.py --test-log /tmp/orbisops-entrypoints-package.log --output /tmp/orbisops-entrypoints-deployment.json
python3 scripts/seed-bundled-skill-routing.py --output /tmp/orbisops-bundled-routing.json
python3 scripts/seed-related-skill-acceptance.py
python3 scripts/seed-workflow-skill-binding-acceptance.py
```

种子通过正常草稿、校验和发布 API 创建独立的 `ops-acceptance-skill-binding`；保留同内容的既有版本。发现更高版本时不会把旧草稿强行发布覆盖。`skill-ops06-related-project-fixture` 是明确标记的人工验收包，不是模型经验。其治理状态或内容被你更改后，种子不会恢复成预设内容。

## 底层绑定与恢复夹具

「OPS-07 显式 Skill 绑定验收」是参数已经就绪时的底层契约夹具。工作流与前后两个 Direct 节点均绑定同一个项目 Skill，验证去重、冻结版本和审批恢复。先前通过浏览器发送 JSON 只验证了这条底层链路，**不能计为用户自然语言使用验收**。结构化输入保留在程序夹具中，正常用户无需编写它。

用户入口重测参见 [自然语言与网络恢复](../2026-09-09-model-network/重跑步骤.md)：只用中文描述目标，系统读取工具 Schema、定位资源、计算时间范围并调用真实 Luna；不会增加必填 JSON 表单。

在工作台审批页，先确认等待，再批准并继续。最后使用页面上的真实 Run ID：

```sh
python3 scripts/inspect-skill-revocation-acceptance.py --workflow ops-acceptance-skill-binding --run "$ORBISOPS_BROWSER_RUN" --status SUCCEEDED --calls 2 --output /tmp/orbisops-binding-receipts.json
python3 scripts/inspect-skill-publication-acceptance.py --run "$ORBISOPS_BROWSER_RUN" --output /tmp/orbisops-binding-budget.json
```

脚本保留只读 SQL、原始结果、实际 MCP 调用记录和目标状态，验证 `REQUESTED_ACTIVE_SKILL`、重复绑定只冻结一次、运行使用的已发布 Workflow version/hash、审批已批准，以及两次真实远端回执。不要把页面打开或 200 响应当成成功。

## 代码边界

只从服务端解析出的 Workflow 定义收集显式 Skill；不把继承项目全部能力当成显式选择，不信任 HTTP 中伪造的内部字段。工作流、节点、AgentScope 与用户显式请求一起归一化去重，超过 3 份拒绝启动，需拆分任务或调整绑定。审批恢复复用原持久化 bundle；不会刷新到新版本。

旧分析 LLM 入口共享冻结加载器和同一 Run 的持久化预算，线程间传递不可变引用；按名称直接读文件的旁路已移除。加载失败不继续降级为无 Skill；只有成功读取并预留预算后才记录加载事件。2026-09-09 已接通仓库原有已授权 Luna/Terra 网关；此前隔离验收环境没有继承该配置，不能据此声称用户没有凭据。Java 合成协议测试仍不证明真实推理质量。

编排绑定校验使用运行态授权目录，支持项目 Skill，同时拒绝跨项目、停用、无路由边界和未授权全局 Skill。管理详情读取最新草稿或版本，运行态已发布指针与审批规则保持原流程。
