# OPS-04 C 重跑步骤

以下从 OrbisOps 仓库根目录 执行。所有凭据保存在忽略且权限为 600 的 `deploy/.env.acceptance`、`deploy/.acceptance-private/`；不要打印或提交。

## 部署与工具审核

```sh
python3 scripts/local-acceptance.py init
python3 scripts/local-acceptance.py up
python3 scripts/seed-local-acceptance.py
python3 scripts/start-observability-acceptance.py
python3 scripts/seed-observability-mcp.py --approve-read-only
python3 scripts/seed-business-workflows.py alert inspection change
```

已有四工具目录需要明确增补 `target_version` 时，执行一次：

```sh
python3 scripts/seed-observability-mcp.py --refresh-catalog --approve-read-only
```

该选项只允许重新发现当前启用的隔离 endpoint；旧策略 hash、审批人和审批时间须保持不变。不会自动批准被拒绝或停用的策略。已存在不同工作流时先核对差异，再用 `--new-version` 发布保留历史的新版本。

历史数据仅可查询最近七天。当前可复用 UTC `2026-09-08T18:18:00Z～18:48:00Z`，中心 `18:33:00Z`。新环境先产生完整业务窗口：

  --center 2026-09-08T18:33:00Z --output /tmp/orbisops-c-evidence.json
cd server
mvn -B -pl orbisops-app -am \
  -Dops04.change.evidence=/tmp/orbisops-c-evidence.json package

`WorkflowChangeVerificationRealEvidenceTest` 读取真实 MCP 原始样本和独立 MySQL 统计，输出同目录 `c-real-policy-results.json`。上下文明确标为组件 fixture，不能代替批准发布。未传参数时该用例跳过，应单列未测。故障脚本只停启隔离 target，finally 恢复，不删除卷；停机前应没有并行流量生成器，以便断言累计计数完全不变。
