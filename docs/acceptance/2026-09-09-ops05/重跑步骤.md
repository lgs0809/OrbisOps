# OPS-05 本地任务分段验收

复查命令使用 `ORBISOPS_C_EVIDENCE_FILE` 环境变量指向本机已采集的 `c-real-component-evidence-second.json`。请先设置该文件路径；变量不生成或代替运行证据。各批次交付中的原始执行日志保持不变。

仓库：OrbisOps 仓库根目录。以下命令在仓库根目录运行。只操作 `orbisops-acceptance` 隔离环境，保留数据卷。数据库不是空库，复用 A/B 权限用户、已审核的只读 MCP 和实际订单目标。

## 启动与初始化

```sh
python3 scripts/local-acceptance.py start
python3 scripts/seed-local-acceptance.py --verify-only
python3 scripts/seed-task-episode-acceptance.py
```

首次安装和真实观测依赖按 `docs/acceptance/README.md`、`docs/acceptance/observability-business.md` 启动。现有机器已完成该步骤。种子通过草稿、验证、发布 API 创建工作流，不写数据库制造发布状态；已有同名不同内容会拒绝覆盖。种子可重复运行，私有记录在 `deploy/.acceptance-private/task-episodes.json`。

修改代码后的完整构建部署入口为 `python3 scripts/local-acceptance.py up`。这会在独立 compose project 内构建本仓库，不删除卷；本批实际使用 Maven 测试后的 JAR 构建镜像，命令和哈希见验收包 `evidence/deploy-backend.py`、`deployment-delivery.json`。数据库 migration 081 是六张新增表，旧的单 Run Skill Episode 保持原义。

## 页面手动操作

1. 打开 `http://127.0.0.1:3302/chat`，使用 `ops_acceptance_admin` 登录。密码只保存在 `deploy/.acceptance-private/admin.json`，不放进报告。
2. 新建对话，选择“隔离验收项目 A”和“OPS-05 会话分段验收 · 目标版本只读核验”。固定使用已发布 v2。
3. 运行下面命令，将输出 JSON 粘贴到输入框并发送；每轮重新生成时间。第二轮可改成“继续核对刚才的目标”，第三轮可改成另一个目标。这些自然语言用来验证将来的语义分段，工作流本身只执行真实 `target_version` 读取。

```sh
python3 - <<'PY'
import json,time
end=int(time.time())-2
print(json.dumps({'question':'读取当前目标版本，保留核对依据。','window':{'projectId':'ops-acceptance-a','environment':'acceptance','serviceId':'ops-acc-a-service-1','startEpoch':end-600,'endEpoch':end}},ensure_ascii=False))
PY
```

4. 打开“任务分段”，展开“追溯信息”，查看消息序号、完整 Run ID、原始上下文哈希及尝试次数；“查看本轮运行”可进入工作台，展开技术详情核对 MCP 证据。刷新或重进能看到同一记录。
5. 当前模型调用开关为关闭，且没有配置 Luna。因此第一轮显示“分段服务不可用 · 待归属”，后续轮显示“等待前序轮次归属”。这是当前环境预期结果，**不是语义分段通过**。主流程依然能继续完成只读工作。

需要真实语义验证时，在模型管理配置唯一一个启用的 `gpt-5.6-luna`，绑定其自己的有效 Provider，并在部署配置启用模型调用。此操作可能产生模型费用，当前验收没有代为开启。分类器不使用默认模型，也不会回退到 Terra 或 gpt-5.5；Luna/Terra 的大小模型约定不变。模型不可用时不消耗两次尝试预算，重新可用后自动补处理。超时或坏响应最多两次，耗尽保留待处理并阻止跳过；目前没有重置耗尽预算的运维界面。


第一条使用临时 MySQL Testcontainers 和标明合成的模型协议响应，验证分段、并发、回滚、午夜和版本规则，不代表真实模型判断准确率。第二条创建三个真实只读运行，验证权限后实际重启隔离后端及其 MCP 连接，保留所有卷；不希望重启时加 `--no-restart`，但此时不能宣称通过重启验收。第三条只读核对已有浏览器操作，不启动新任务。

检查脚本同时导出可直接执行的 `*-inspect.sql` 和带表头的 `*-inspect.tsv`。通用 SQL 模板在 `scripts/fixtures/ops05-task-episodes-inspect.sql`，将 `REPLACE_WITH_SESSION_ID` 换成自己的会话即可。MySQL 地址 `127.0.0.1:13362`，数据库 `orbisops_acceptance`；连接凭据只在私有部署配置中。

## 数据边界

完整原始上下文与本轮回复冻结在独立来源快照中，分类结果不会写回普通聊天或记忆。历史运行只能使用留存上下文重建时，明确显示“非完整回放”。超过来源大小、工具数或已知段数量上限时标记 `SOURCE_BLOCKED`，不截掉关键内容后假装分类成功。

整理产物按 Episode、revision、类型和生成配置去重，触发来源仅合并为原因。当前只生成 PROGRESS／UNKNOWN，不能据此宣告业务成功或开放 Skill 加载；成功经验门槛属于 OPS-06。审批、正在执行的工具和前序未归属轮次不会被后台分段绕过。
