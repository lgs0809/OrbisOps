# 2026-11-03 后台模型持续退避验收

本批对应用户明确的“后台一直指数退避”。它覆盖 Episode 分段/整理、记忆抽取/摘要及向量补做、Skill 独立复核与演化的模型技术失败。前台 HTTP 的有限重试、Run 期限、Workflow 执行预算和生产写审批维持原约定。模型仍为 gpt-5.6-luna / gpt-5.6-terra。

## 实现

- 复用已有持久队列、Spring 调度、MySQL 租约/epoch，统一指数退避与按任务确定的向上抖动，累计次数不清零。本地等待上限一小时，Provider Retry-After 只延长。
- 旧 RETRY_EXHAUSTED/EXHAUSTED/技术 FAILED 由正常后台维护渐进恢复：每 30 秒轮转一类，单次最多恢复一条；保留原任务、原 owner、输入 hash、累计次数和失败原因，另记恢复审计。配置关闭、来源失效、取消与明确撤权均阻断。
- 规则记忆先可用，模型来源与待补做状态明确。初次摘要和补做都在事务外调用模型，完成事务再核验租约并投影；不回填 2230 条历史消息/6690 条完成任务。
- SEMANTIC 明确区分主动词法模式与临时 embedding/写向量失败。后者使用同一持久任务延期，仍可检索词法；新向量的可见性同时核验已完成任务、epoch、当前来源 hash 和原 owner 权限。复用 Spring AI VectorStore，不声称 MySQL/PG 两库原子事务。
- 合法空结果、UNKNOWN、NO_CHANGE、证据不足 REVIEW、无复用模式是业务结果；同一冻结输入不为凑成功而反复提问。固定来源完整性非法隔离。分组证据不足保留私有未分类事实，不要求人工开始调查。
- 原 owner 策略由 Security 的窄 Port 提供，项目授权沿原读取规则；合法 USER 无项目范围继续可用。project.enabled=0 本身不新等同撤权。

详细契约见 ../../development/background-model-retry.md；只读核对 SQL 为 ../../../deploy/acceptance/background-model-retry-inspection.sql。
